# 安全说明

本文描述当前代码的保护范围与实现限制，供运行和修改协议时参考。项目尚未完成独立安全审计。

## 密钥与口令

- 用户分别生成 RSA-3072 签名密钥和加密密钥。
- 私钥在客户端用口令派生密钥与 AES-GCM 加密保存；服务端只接收公钥。
- 服务端保存带盐口令派生哈希。派生实现优先使用 Argon2id，缺少该依赖时使用 Scrypt 回退。
- 登录需要口令校验与签名私钥挑战；丢失本地密钥库后无法仅凭密码恢复原私钥。

## 通信与本地存储

文本在客户端加密并签名，文件使用独立文件密钥。服务端正常中继流程不需要用户私钥、会话密钥或通信明文。

服务端仍可访问账号、通信对象、时间、文件名、文件大小和其他中继元数据。本地聊天数据库会保存解密后的明文，下载文件也以明文落盘；私钥库加密不等于聊天数据库加密。

## 身份与传输信任

- 客户端从服务端获取服务端加密公钥，尚未提供独立的密钥固定或证书信任配置。
- 公钥目录响应包含服务端签名，但当前 API 客户端和 GUI 尚未验证该签名。
- 好友记录的 `trusted` 状态直接由程序设置，尚未提供人工指纹核验流程。

这些限制意味着当前实现不能对恶意服务端替换公钥或首次连接时的中间人攻击提供完整防护。消息加密和签名需要与可信公钥身份绑定一起评估。跨主机运行前还需要配置可信的 HTTPS/WSS 和身份信任机制；默认启动命令仅监听本机。

## 会话与令牌生命周期

- 会话信封记录 `expires_at`，但接收端尚未强制检查过期时间。
- 消息序号通过内存中的 `ReplayTracker` 检查，客户端重启后不会保留历史序号。
- 当前静态 RSA 会话密钥封装未实现前向保密或双棘轮协议。
- 服务端密钥和访问令牌保存在内存中，重启后会变化或失效；尚未提供完整的令牌有效期与撤销机制。
- WebSocket URL 包含访问令牌，部署和排错时应避免记录或共享完整连接 URL。

## 消息投递

在线事件与离线拉取共用持久化消息队列，尚未提供完整的客户端处理确认和跨连接去重语义。当前设计不能保证每条消息只处理一次。

## 文件扫描

默认规则检查文件大小、危险扩展名、EICAR 测试串和部分危险文本；扫描函数还接受可选哈希黑名单。文件扫描通过仅表示通过这些规则，不代表文件无恶意内容。

接收流程会先将解密文件写入目标路径，再进行扫描；复检失败时删除文件。需要更严格隔离时，应改用受控临时目录和独立扫描进程后再发布文件。

## 修改协议时的检查重点

更改序列化、签名字段、附加认证数据、会话生命周期或文件清单时，应同步修改协议测试；同时检查旧数据兼容性、错误分支和本地明文处理方式。自动化测试命令见 [项目首页](../README.md#运行测试)。
